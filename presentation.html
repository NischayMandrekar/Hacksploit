Architecture
A Dual-Plane, Lifecycle-Aware Detection System
KYC is not a one-time onboarding check. The system screens at application, re-scores on lifecycle events, and presents explainable evidence to analysts — all through a single modular backend with no external message brokers.
Zero external broker dependency — 100% PostgreSQL row-level locks · RBI KYC Directions: ongoing due diligence is mandatory, not optional 2 / 7
Evidence Layer
What Each Signal Detects — Documents · Behaviour · Biometrics
Document & Image Forensics
Fast plane — < 10ms — Pillow only
Dimension anomaly: AI generators output 1024×1024, 512×512. Camera photos don't.
EXIF anomaly: Missing camera metadata or Software = "Stable Diffusion" tag.
JPEG quality factor: Round values (quality=95) = editor. Camera profiles are never round.
Slow plane — async worker — CPU
ELA (Error Level Analysis): Pasted/edited JPEG regions compress at different error levels than the surrounding image.
FFT Spectral: GAN upsampling leaves characteristic frequency-domain grid artifacts.
TruFor (GRIP-UNINA): Forgery localization heatmap. Selected baseline: only 6/26 DeepID 2025 teams beat it.
InsightFace: Face crop from ID → embedding. Selfie → embedding. Cosine distance + face-swap probability score.
Not included: C2PA manifests (absent on >99% of Indian fraud tooling — zero discriminative value). UniversalFakeDetect (distribution shift to identity documents is unvalidated).
Behavioural Pattern Analysis
At ingestion — M0 + M1 features
Velocity burst: ≥ 4 applications from the same device fingerprint within 1 hour.
Session anomaly: Session < 30s — pre-filled form, not live input.
DOB email spread: Same date-of-birth seen across multiple distinct email addresses in 4 weeks.
Device reuse: Same device fingerprint hash on ≥ 3 profiles → graph edge.
Credit velocity: velocity_6h, velocity_24h, velocity_4w counters from application history.
Post-onboarding continuous monitoring
Lifecycle events (account_activated, device_changed, velocity_spike) re-score the identity graph cluster in the async worker.
Dataset: BAF NeurIPS 2022 — 1M records, temporal train/test split to prevent leakage.
Biometric Signals
What we include
Face cosine distance: ID document face crop embedding vs. selfie embedding via InsightFace.
Face-swap probability: InsightFace swap-detection head score.
is_selfie_missing flag: Absence is a signal in M3 — not a silent pass.
Honest limitations
FinCEN Nov 2024: Deepfake video streams are used specifically to pass biometric checks. A live human can submit synthetic documents and pass face liveness.
eKYC-DF dataset (IEEE): 228k+ fake videos. Deepfake-resistant biometric KYC remains an open research problem.
Our treatment: Biometric scores are additive features into M3 — not gates. A shared address or device alone does not prove fraud.
All signals produce EvidenceStatus: PRESENT / ANOMALOUS / UNAVAILABLE — never a silent default.
All three evidence classes feed the M3 fusion layer as calibrated input features — not as independent pass/fail gates 3 / 7

Research Contribution
Does Detection Hold When the Fraudster Hides Connections?
The central experiment other teams don't run: deliberately corrupt the identity graph and measure degradation across all four models under fixed seeds and a held-out test set.
Controlled attack matrix
E0
Clean: Full graph, all evidence. Establishes baseline for fair comparison.
E1
Missing links 10–30%: Identity edges randomly removed. Simulates fraudsters switching phone numbers or using proxy IPs.
E2
Adversarial camouflage: Fraudulent nodes deliberately linked to legitimate profiles to dilute cluster purity.
E3
Missing modality: Document or selfie evidence dropped. is_doc_missing = 1 / is_selfie_missing = 1. System must abstain safely, not auto-approve.
These are controlled corruption tests, not real-world attack simulations. Randomly deleting edges does not reproduce an intelligent attacker. Results will be reported with this qualification.
Why this is novel: The Nguyen & Chiu 2026 paper establishes the clean-data baseline. No published work combines missing graph edges + cross-source evidence loss + explicit missingness features in the fusion layer under one fixed evaluation protocol.
PR-AUC under graph degradation (hypothesis — not yet validated)

Three demo scenarios — what judges will see
Scene 1 — Clean Applicant
Single application. No graph links to other profiles. Document passes EXIF + ELA checks. Face embedding distance within threshold. Velocity normal.
APPROVE < 200ms · fast plane only
Scene 2 — Hidden Synthetic Ring
7 individually plausible applicants connected by a shared phone hash. Each application passes M0 rules in isolation. M2 graph engine detects the cluster via ego-network density and shared_phone_degree = 6. Analyst sees labelled identity graph.
FLAG_REVIEW M0 misses · M2 + M3 catch · ring visible in analyst console
Scene 3 — Adversarial Stress Test
Same ring with 30% of graph edges removed (fraudster switched phone numbers). M2 graph signal degrades. M3 fusion falls back on OCR name contradiction and velocity burst. Demonstrates why multi-source fusion outperforms any single model under real adversarial conditions.
REJECT M2 degrades · M3 holds via cross-modal evidence · SHAP card explains each contributor
Every flagged application produces a SHAP attribution card showing which features drove the score — graph linkage, OCR contradiction, missing selfie — giving analysts explainable, actionable evidence rather than a black-box probability.
